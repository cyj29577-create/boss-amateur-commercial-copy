# 改稿模式执行流程
版本：v1.3

有原稿默认局部改。保留原意、立场、有效信息、活人感与未受影响部分；只在明确要求全改或核心立意/因果整体不成立时重构，说明必要范围。

1. 读全文并锁定用户/甲方修改要求，按07建保真卡。先按09实算原稿L0、上限与剩余预算，再修改；原稿超限先定压缩计划。
2. 定位问题及依赖，明确是替换还是必要新增。句式雷同、禁词、过渡、隐晦、品牌风险优先替换原句，不在后面追加解释。标题范围变了要核正文；局部承载不了因果才扩大到相邻句段。
3. 确缺必要逻辑执行“补一处、压一处”。优先一句承担相邻节点，按09顺序压缩，保护动作、话术、标准、案例和必要商业链路。不借零脑补给每节点多加一句。
4. 对全文反向映射05/06，检查修改依赖与全稿安全，不擅自优化无关段落。涉及雷同按07重构，①—⑥尤其④⑤⑥完整参与，不反转公司因果或恢复品牌负面旧S3。
5. 比较L0、L1和差值。默认不明显长于原稿；无必要新增却明显增长即不合格，重新压缩。800—950不是改稿补字任务。必要新增须记录缺了什么、补在哪、压了哪，不仅声称“更清楚”。
6. 强制执行16全部适用Gate；形成最终字符串，按01全文扫描、09实算。修改一字也重扫重算。局部修改不等于只扫植入段。

默认完整修改稿按04固定首行＋正文＋Tag；必要说明放稿外。用户只要替换句时只给替换句，同时核可得全文替换后的总数；缺全文不能宣称整篇通过。发现指定保留段落有事实/品牌问题时指出，不靠换词掩盖，也不把需要用户补证据的内容伪写成事实。
