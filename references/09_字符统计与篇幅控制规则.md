# 字符统计与篇幅控制规则

版本：v1.3

## 唯一计数口径

<!-- contract:count:begin -->
最终完整交付≤1000字符。标题、正文、Tag、标点、英文、数字、#、空格、可见换行等全部计入；按最终Unicode字符序列实际计算（Unicode码点），可见换行=1，boss=4，#BOSS直聘=7；任何修改后重算。
<!-- contract:count:end -->

这是商业稿的最终完整交付上限，不是本Skill文件、案例教学注释或纯诊断报告的长度上限。多篇独立稿分别核算；同一篇的标题、正文、Tag不得拆开冒充多个额度。用户要求更短时采用更短上限。

## 默认目标容量

正常素材充足的完整写稿，默认目标容量为约800–950字符；这不是新的硬性下限，不得为凑字数灌水，也不能为了满足≤1000字符主动写得过短。只有素材不足、用户明确要求短稿或文章自然写完时，才允许明显更短。≤1000字符仍是硬上限，完整统计口径不变。

约800–950字符同样按完整交付字符串计算，含固定标题前缀。此目标适用于正常素材充足的完整写稿，不把它当成所有改稿的补字任务；局部修改仍遵守11的最小充分改动边界。

## 固定待交付字符串

先把实际要复制发布的全部内容形成一个字符串，保留真实空格、空行和换行。标题后一个换行计1，空一行通常含两个换行计2。财经固定前缀`财经-标题：`、小老板固定前缀`小老板-标题：`分别计6、7字符；它们不属于标题正文，但属于可见交付文字，必须计数。若交付另有“正文：”等可见标签，这些标签也计数。不要计数后再添加标签、话题或末尾换行。

文件层的CRLF或CR只代表一个可见换行时，在最终交付字符串中统一为LF再计算；交付也必须使用同一字符串，不得只在统计时删除字符。不要strip、去空格、删除零宽字符或做Unicode正规化来压缩计数。其他Unicode分隔符按实际码点计入。

一个Unicode码点计1，不按UTF-8字节、UTF-16代码单元、汉字字数或视觉字形计。单码点emoji计1，组合emoji包含的连接符、修饰符各计1；组合附加符也各计1。保留在最终字符串中的不可见码点同样计入。

## 可复用计数实现

Python 3：

```python
def final_text_and_count(text):
    final_text = text.replace("\r\n", "\n").replace("\r", "\n")
    return final_text, len(final_text)

final_text, count = final_text_and_count(text)
assert count <= 1000
# 后续原样交付final_text；任何修改后重新执行。
```

JavaScript：

```javascript
const finalText = text.replace(/\r\n?/g, "\n");
const count = Array.from(finalText).length;
if (count > 1000) throw new Error("完整稿件超限");
// 原样交付finalText；不要使用text.length统计Unicode码点。
```


## 压缩顺序与保护项
先合并功能重复→删重复解释→无效修饰→同义重复→冗长过渡→非必要背景→最后才碰核心方法。保护具体动作、可复制话术、判断标准、有效案例、必要因果、商业链路和事实/风险边界。核心方法若确须减少，保留本题真正解决问题的动作；不能把内容价值压没。不要只删标题Tag而交付时补回。

改稿先计算原文L0、当前上限（默认1000，用户更短则更短）及可用预算。没有必要新增信息时以不增长为操作目标，不明显长于原稿；确需补信息则“补一处、压一处”，优先一句承载相邻节点。记录L1、差值与新增信息理由；无必要信息却明显增长须重新压缩，不自设容许增长百分比。接近上限不能先扩写再大砍。800—950目标不适用于给短原稿补字。

## 机械预检与交付
可运行 `python scripts/check_text.py 稿件.txt --original 原稿.txt --mode edit`（按环境使用可用Python）。无原稿省略original；写稿用write，审稿用review。输入须是完整实际交付字符串，不能只有正文。脚本输出字符数、全文禁词位置、前后差值、SHA-256与人工待核状态；超限/禁词返回非零。增长仅作为待解释信号，脚本不会代替语义判断。

保留实际待交付文本，LF即一个可见换行；任何改动后重跑，交付同一字符串。不要strip、去空格或正规化Unicode以规避统计。脚本不自动修改原文。

核验说明放在稿外；不能实际运行时标记“未实际计数”，不能凭目测判可送。只给替换句须用全文替换后核算，缺全文只能报告局部数。多篇分别核算。纯诊断报告、规则说明不受成稿上限约束。
失效旧规则“正文≤900且标题Tag不计”不得恢复。
